# 固定悬浮停止窗口与文字同步停止

用户点击 Mac 的开始控制按钮后操控 Windows，希望有固定悬浮窗口，点击或用快捷键停止键鼠和文本控制。沿用原有权限和手动键鼠模式，不增加画面采集。

## 交互

手动会话建立后，两端在当前显示器工作区右上角显示固定、不可拖动的置顶悬浮条，展示设备名、控制方向、停止按钮及本机快捷键。窗口不抢焦点、不进入任务栏，切换主窗口页面或隐藏主窗口后继续可见。正常结束、断线或取消配对后隐藏。

控制端光标仍居中锁定；因此正常远控鼠标可以直接点击被控端（例中的 Windows）悬浮条停止，不需要为点击本机窗口解除锁定。Mac 悬浮条明确提示使用 Control+Option+Esc 或对方的按钮；Windows 使用 Ctrl+Alt+Esc。被控端自己的本地鼠标也可点停止。不会放行桌面上任意位置的点击，避免误操作 Mac。

「停止共享」立即释放当前会话的键盘/鼠标，再暂停该配对设备双方的文本同步；保留其他设备及文件传输。暂停以现有设备级 clipboard=false 表达并保存，需要时重新开启设备卡片的文本同步。全局快捷键、托盘和主界面主动停止使用同一操作；正常自动跨屏回穿保持原有独立剪贴板行为。

## 实现边界

- 核心 stopSharing(expectedSessionId?) 支持会话 ID 校验，防止旧悬浮窗口停止新会话。控制快照增加可选 id；旧代码仍可读取 mode、peer 等字段。
- capabilities 增加 stopSharing:true；新手动发起端在截获前要求对端支持完整停止，提示两端升级0.1.6。
- control/stop 的 stopClipboard:true 请求仅修改对应配对通道，并明确返回 clipboardStopped。新的会话不能被旧停止请求关闭或暂停。双方先在内存撤销权限，再排空已授权的剪贴板写队列；外发中的剪贴板请求可中止，停止后的入站请求不再进入 OS 剪贴板。
- 剪贴板事件提供不可恢复的授权租约（全局和设备代次）；主进程在真正执行 writeText 前重验，权限撤销后再开启也不会执行旧排队内容。异步读入过程中也重验授权。ClipboardSync 提供 flush() 供停止确认等待；队列可通过独立 backend 测试。
- 独立 ControlPanel BrowserWindow 使用专用 preload 和 IPC，仅允许读取自身公开状态、订阅状态、停止自身会话。主窗口通用 IPC 不向悬浮窗开放；校验主 frame、webContents、页面地址和会话 ID。页面加载失败/窗口意外关闭时停止对应会话。
- 面板通过 Electron screen 定位，包含 Windows 负坐标及工作区，showInactive 不夺焦点；主窗口仍保持原有隐藏到托盘行为。原生输入协议无需修改。

## 验收

真实 HTTPS 服务验证双方设备文本开关关闭、其他设备不受影响、旧会话停止不影响新会话、入站读取/排队写入/外发中请求在停止后被隔离、排空后的剪贴板不再变化。用真实 Electron 独立窗口和模拟输入后端验证双端悬浮条、置顶/固定/焦点、按钮会话绑定、专用 IPC 拒绝越权、快捷键路由及主窗口隐藏不影响面板。使用假的输入适配器避免在用户桌面自动接管键鼠。原生输入、文件传输与签名检查回归后发布0.1.6；物理双机点击和手感限制明确记录。
