# 局域网手动键鼠远控

用户将需求收敛为键鼠控制，不传输屏幕内容。复用现有可信配对、两端键鼠授权、加密有序输入通道、原生截获及断线恢复；不增加屏幕采集、WebRTC 或屏幕录制权限。

在「设备协同 → 已配对设备」增加「开始控制键鼠」。点击后主动接管指定设备，无需将鼠标推过左右屏幕边缘，也不依赖设备位置/跨屏入口设置。控制端继续居中锁定隐藏本机指针并保存原位置；被控端保留当前鼠标位置，正常移动、点击、滚轮与键盘输入。Windows 可跨其内部多块屏幕。此模式到达桌面边缘不返回本机；通过现有 Ctrl+Alt+Esc（Mac Control+Option+Esc）或被控端停止按钮退出，恢复控制端原位置。正在控制/正在被控制状态及模式清晰可见。

保持原来的自动跨屏行为，两种模式共用独占会话，不允许同时控制两台设备。文件传输及文本剪贴板仍使用原功能及其独立开关。用户需要直接看对方显示器、KVM 切换后的画面或其他既有显示方式，应用不提供画面预览。

## 协议

- 新增已配对、已授权的 `POST /api/localshare/v1/control/capabilities`，响应 `{version:1,manual:true}`。手动模式在截获本机前验证；旧端返回未知路径或不支持时明确提示升级，不能静默退化为跨屏模式。
- `Control.start(fp,side,y,interaction="edge")` 支持 `"manual"`；控制开始请求可携带 `interaction:"manual"`，省略仍是 edge。接收端严格校验、将 manual:true 传给 InputAdapter.receive，并回传 interaction。手动模式忽略来源的左右位置与 entryDisplay，保留对方指针当前位置。
- 原生 `receive` 命令增加 `manual:true`。该模式禁止边缘返回并保留当前指针；正常 release、错误、心跳、应急退出逻辑一致。原生协议升至4，完整应用包必须包含匹配的辅助程序。
- 快照中控制状态增加可选 interaction 和 fingerprint，供 UI 标记模式及目标。新窄 IPC `controlDevice(fingerprint)` 只允许配对且已授权设备；先检查本机模块，再调用手动模式。

## 验证

真实双 HTTPS 服务覆盖能力探测、默认兼容、非法模式、双方授权、有序输入、旧端拒绝、会话互斥及停止恢复；原生自检覆盖手动接收位置和边缘不退出，并验证原跨屏回穿不变。界面点击/IPC 检查使用独立模拟输入适配器，避免夺取用户当前键鼠。完成类型、格式、原生构建、Mac 签名和发行包检查后发布 0.1.5；真实物理双机手感另行明确记录。
