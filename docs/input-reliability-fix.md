# 0.1.2 键鼠流畅性与双向输入修复方案

用户实测：鼠标移动卡顿；Mac 控制 Windows 时 Mac 光标仍移动，Windows 可移动但点击与键盘无效，反向控制可用。

已确认源码问题：
- 原生回归测试确认 Mac 事件的 `down` 字段由 Objective-C 比较表达式装箱为数值 1/0；主进程严格要求 boolean，导致 Mac 的点击和键盘被丢弃。输出已改为显式 `@YES` / `@NO`。
- 每次控制长轮询都创建并销毁 HTTPS Agent，重复 TLS 握手，且人为等待 12ms。
- Mac 仅隐藏光标，未解除物理鼠标与本机指针的关联；原生进程没有检查完整键盘事件掩码，主进程也不等待截获成功确认。
- Windows 没有检查 SendInput 返回值，无法辨别系统拒绝输入。不能在无实机证据时直接把此用户的点击故障归咎于 UIPI。

实施顺序：
1. 增加真实 HTTPS 回归，验证连接复用、证书不匹配仍被拒绝；连接池按本机身份、对方 IP、端口及已配对指纹隔离，撤销与退出时关闭。
2. 在原有协议上以短批次发送输入，合并尚未发送的连续移动，保留点击/按键屏障、序号和重传语义，避免积压。测量同机延迟与握手数，不能作为两台物理设备的网络延迟结论。
3. 在控制状态机中增加原生模块确认：本机确实截获成功、对方确实准备好注入之后才启用，失败立即释放本机和对方状态。
4. Mac 使用 HID 事件过滤、验证键盘/按钮/移动所需掩码与发送权限；截获时锁定并隐藏本机指针，退出/超时恢复；缺少权限时明确说明辅助功能与输入监控检查位置。
5. Windows 检查每次 SendInput 结果，并以扫描码注入常用按键，报告系统拒绝；不自动提权或绕过安全桌面。
6. 编译两套 helper，运行状态机、协议、传输及桌面回归，Mac ZIP 严格签名校验，发布双平台 0.1.2。保留必须由真实 Windows / 双机确认的验证边界。

参考：Apple CGEvent.h 事件掩码权限说明、Quartz Display Services MouseCursor 文档；Microsoft SendInput 与 KEYBDINPUT 官方文档；Node HTTPS Agent 官方文档。
